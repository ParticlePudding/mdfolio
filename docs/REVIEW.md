## 1. レビュー方法

1. **机上レビュー**: 次の観点のチェックリストで仕様書を通読した。
   - 要求の充足（依頼内容: ローカルの HTML / JS で動く、Markdown 文書の表示サイト、再配布可能、テスト済み）
   - 実現性（ブラウザの制約下で本当に動くか）
   - セキュリティ（第三者の Markdown を開いたときの安全性）
   - ライセンス（再配布時の義務を満たせるか）
   - 整合性・曖昧さ（未定義の動作、矛盾、解釈が割れる記述）
   - テスト容易性（各要件を検証できるか）
2. **実機検証**: 実現性に関わる前提は、推測で済ませず実物で確かめた（2 章）。

検証環境: Chrome for Testing 153.0.8010.12（ヘッドレス、Linux）、Node.js 22.23、Playwright 1.63。
対象ライブラリ: markdown-it 15.0.3、markdown-it-footnote 4.0.0、DOMPurify 3.4.17、highlight.js 11.12.0、KaTeX 0.19.1、mermaid 12.3.0 / @mermaid-js/tiny 12.3.0。

## 5. 実装・テスト後の追記（2026-11-13）

このレビューは仕様書と小さな実験に基づくもので、できあがった物を動かして確かめたわけではありません。実装後のテストで、レビューでは見つけられなかった問題が 16 件見つかりました。一覧と対応は [TEST_REPORT.md](TEST_REPORT.md) の 6 章にあります。レビューとしての反省点を残します。

| 見落とし | なぜ見落としたか | 今後のレビューで確かめること |
|---|---|---|
| 図（Mermaid）の中の画像指定から、外部へ通信が発生した（T-08） | 「安全な設定で使う」という前提を、ライブラリの説明だけで信じた。RV の検証では、文書の `<img>` しか試していなかった | 「通信しない」のような性質は、経路を列挙して机上で潰すのではなく、実際に通信を観測して確かめる。第三者のライブラリが独自に持つ読み込み経路を疑う |
| アクセシビリティの不備 5 件（T-13） | チェックリストが「名前を付ける」「コントラスト」程度で粗かった | 独立した検査エンジン（axe-core）を、レビューの検証の段階から使う |
| スクロールバーを常に表示する環境での見た目の崩れ（T-15） | 検証に使ったブラウザーがスクロールバーを隠す設定だった | 検証環境が実際の利用環境と違う点（スクロールバー、フォント、ロケール）を先に洗い出す |
| 大きな文書の表示時間が目標ぎりぎり（T-11） | 性能の目標値を、根拠となる計測なしに決めた | 目標値を決める前に、同梱ライブラリの処理時間を計っておく |

残課題（4 章）の現状:

- 1（Firefox / Safari）: Firefox のエンジン（Gecko 160）と Safari 系のエンジン（WebKitGTK 2.52）で、主要機能の自動確認ができた（V16 の時点では導入できないと判断していたが、同じエンジンを使う別の配布物を使えた）。製品版そのものでの確認は、引き続き手動確認の対象。
- 2、3: 変わらず（手動確認の対象）。
- 4: 変わらず。

## 6. 1.0.1 の変更についてのレビュー（2026-11-13）

サンプルを公開ページ（別のページのフレームの中に表示するホスティング環境）に置くための変更について、仕様（SPEC.md 1.2）を実装の前後に見直した記録です。レビューアは実装者自身で、第三者によるものではありません。

| # | 重要度 | 指摘 | 対応 |
|---|---|---|---|
| A-1 | **高** | ホスティング側がページへスクリプトを差し込む環境では、HTML に書いた CSP を外さないと動かない。外すと「外部と通信しない」ことを HTML 自身では保証できなくなる。それなのに開始画面が「外部には送信されません」と表示するのは、言いすぎになる | 変換後の HTML を「お試し用」と位置づけ、保証できない範囲を仕様に明記（6.1）。開始画面と使い方の文言を、お試し用の公開ページであることを伝えるものに差し替える設定（`hosted`）を追加 |
| A-2 | 高 | フレームの制限で保存が止められる環境では、「サイトとして書き出す」と添付の保存が、押しても何も起きない操作になる | 設定 `allowDownloads` を追加し、該当する操作を画面に出さない。添付へのリンクは、保存できない旨の表示にする |
| A-3 | 中 | 外部の画像を表示する切り替えも、ホスティング側の CSP で止められる環境では動かない。利用者が保存済みの「表示する」設定を持っている場合の扱いも決める必要がある | 設定 `lockExternalImages` を追加。切り替えの項目を出さず、保存済みの設定や `allowExternalImages` より優先する。起動時の CSP の追加（SEC-10）は変わらず行う |

解消できなかったこと:

- 実際のホスティング環境（Claude のアーティファクト）と、スマートフォンの実機では、動作を確かめられない。公開の操作そのものは成功した（A-9 の対処のあと、2 つのページを公開先が受け付けた）が、公開されたページを開いて表示と操作を確かめることはできなかった（確認に使えるブラウザーが、公開先にサインインしていなかった）。確かめたのは、公開されている説明をもとに条件を模したフレーム（別オリジン・サンドボックス・画像を `data:` / `blob:` に限る CSP・スクリプトの差し込み）と、タッチ操作を模したブラウザーである。実環境との違いが残る可能性があり、報告書（8 章）に未確認として記載した。
- 配布済みの `mdfolio-1.0.0.zip` は、日本語のファイル名に UTF-8 の印が付いておらず、Windows の環境によっては、展開すると `sample-docs` のファイル名が文字化けする（報告書 T-19）。1.0.0 のレビューとテストでは、zip の中身のファイル名を Windows の扱いに照らして確かめていなかった。作り直した zip も、印が付いていることを機械的に確かめただけで、Windows の実機では展開していない。
